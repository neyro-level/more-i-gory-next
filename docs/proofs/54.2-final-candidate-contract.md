# TASK 54.2 — final technical-preview candidate contract

Date: 2026-09-21
Scope: technical preview `more-previu.tw1.ru`; production is excluded.

## Candidate rule

The PR head first passes the exact-head RISKY gate and is squash-merged through
the canonical SourceCraft path. The PR-head tree must then equal the resulting
`main` tree. Any tree drift is a hard stop.

Only after that equality proof, exactly one Linux-built standalone archive is
packed from clean exact merged `main`. `RELEASE.json` contains the resulting
`main` SHA. The SHA-256 sidecar, archive digest, installed release path and
runtime smoke result are recorded in the Task Manager execution ledger after
the immutable archive exists. They are not written back into Git, because such
a commit would create a different `main` SHA and invalidate the manifest.

A pre-merge archive is never the exact-main candidate and must be invalidated.
This procedure never promotes the archive to production.

## Invalidated runtime proof

After installing the frozen archive on the technical preview, repeat only:

- archive sidecar, manifest SHA and installed digest equality;
- `current` symlink, systemd service and loopback health;
- shared writable Next cache and absence of new permission errors;
- Nginx/TLS and preview-wide `noindex, nofollow` boundary;
- representative public routes, 404 and minimal browser console smoke;
- internal revalidation through the canonical trailing-slash endpoint.

Do not repeat database migrations, restore, credential rotation, S3 mutation or
enabled lead intake unless the frozen candidate changed the corresponding
runtime contract. Keep `NEXT_PUBLIC_LEADS_ENABLED=false` after proof.

## Terminal evidence location

The immutable tuple `exact main SHA + SHA-256 digest + preview release path +
smoke result` is terminal external evidence in `EXECUTION_LEDGER_V1`. The
release checklist becomes terminal only after that tuple and the post-merge
tree-equality proof both pass.
