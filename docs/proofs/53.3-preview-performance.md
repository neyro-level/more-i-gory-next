## Writable Next.js cache repair

The active immutable release was owned by `root`, while the service runs as
`deploy`. Next.js could not create `.next/cache`, producing `EACCES` during
image and tag-cache operations.

The runtime contract now keeps one shared writable directory at
`/opt/moreigory/shared/next-cache` and links every immutable release's
`.next/cache` to it. The active preview release received the same surgical
repair, the service restarted healthy, the runtime user write probe passed and
no new cache `EACCES` was observed.

`REVALIDATE_SECRET` hashes matched across Secret Master, the server env file and
the running process. The authenticated canonical endpoint with a trailing slash
returned `200` and revalidated the sitemap tag. The earlier `401` was caused by
the no-slash URL redirect, not secret drift.
