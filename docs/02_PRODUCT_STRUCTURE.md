### 1.2. Зарезервированные namespace

```text
/analitika/<slug>/              # активируется EPIC 18
/novostroyki/                   # активируется EPIC 17
/novostroyki/<complex-slug>/    # canonical URL ЖК
/komplex/<slug>/                # reserved-only
/zastroyshchik/<slug>/          # активируется EPIC 17
/journal/*                      # reserved-only; контент остаётся в /analitika/*
/agenty/*                       # reserved-only
```

До указанного эпика reserved namespace не получает route, redirect, страницу в
sitemap или навигации. EPIC 17 активировал `/novostroyki/`,
`/novostroyki/<complex-slug>/` и `/zastroyshchik/<slug>/`; `/komplex/<slug>`,
`/journal/*` и `/agenty/*` остаются reserved-only. Комбинации «локация × тип», например
`krym/yalta/novostroyki`, разрешаются только по whitelist после появления
самостоятельного поискового интента и фактического контента. Автогенерация
тонких URL запрещена.

### Technical preview navigation

По решению владельца от 2026-09-20 local/staging contour является редакционным
workspace. В нём отдельное меню `Все страницы` обязано показывать все
зарегистрированные маршруты, seed-регионы, seed-статьи и три явно технических
шаблона dynamic pages. `hidden`, `draft` и отсутствующие business facts не дают
`404` владельцу: маршрут показывает честный scaffold с пометкой preview.

Это не меняет release/index contract:

- preview scaffold всегда `noindex` и вне sitemap;
- реальные project/complex/developer slugs по-прежнему создаются только из
  `published` Payload entity;
- production contour возвращает `404` для технических fixture-slug;
- preview visibility не переводит content row в `PASS` и не разрешает сильные
  claims, цены, доходность, кейсы или выдуманные сущности.

## 3. Page Definition Registry

Этот registry является обязательным pre-implementation gate. `Index: yes` означает
планируемую индексацию только после прохождения индивидуального `Content Gate`.
Не пройденный gate = страница не индексируется и не входит в sitemap. В
local/staging preview она остаётся доступным владельцу редакционным scaffold,
но не заменяется тонким публичным текстом и не считается release-ready.

### PAGE-001 — Главная

- **URL:** `/`
- **Primary Intent:** познакомиться с инвестиционным бюро и выбрать следующий путь.

  дата актуальности; путь после заявки.
- **Объекты:** карточки регионов, Project cards, пример Project Passport.
- **Доказательства:** опубликованная методика, источники проектов, реальные эксперты; цифры и кейсы только после проверки.
- **Внутренние ссылки:** federal hub, Крым, Архыз, Алтай, `/obekty/`,
  `/metodika/`, `/analitika/`, `/podbor/`.
- **Primary CTA:** `Получить инвестиционный разбор`; secondary — `Сравнить регионы`.
- **Index:** yes.
- **Content Gate:** готово позиционирование, минимум 4 полных паспорта, методика и подтверждённые сведения о команде.

### 6.1. Core rule

> Один устойчивый поисковый интент — один основной индексируемый URL.

### 6.2. Index

Index:
- `/`;
- federal hub;
- regional/segment/local commercial pages from approved registry;
- `/obekty/`;
- full Project Passports;
- `/analitika/` and approved articles;
- `/metodika/`;
- `/podbor/`;
- `/o-kompanii/`;
- `/kontakty/`.

Noindex / exclude from sitemap:
- `/investicionnaya-nedvizhimost/sochi/` при `status=stub`;
- filter states;
- sort states;
- draft content;
- lots;
- technical routes;
- form success/error routes;
- privacy/consent;
- tag/category/author archives unless separately approved.

### 6.3. Canonical

- self-canonical for indexable pages;
- filtered `/obekty/` states canonical to `/obekty/`;
- one Project = one canonical path.

### 6.4. New URL Gate

Новый индексируемый city/segment/strategy URL разрешён только если есть одновременно:
1. самостоятельный SERP/search intent;
2. реальный ассортимент или самостоятельная аналитическая ценность;
3. уникальная экономика/риски;
4. собственные inbound/outbound links;
5. владелец данных и процесс актуализации.

### 6.5. Structured Data

- `BreadcrumbList` — для indexable hierarchy.
- `Article` — для аналитики.
- Organization/LocalBusiness — только при соответствии фактическим данным.
- `FAQPage` — только если FAQ видим и актуальные поисковые правила позволяют разметку.

Structured data обязана совпадать с видимым контентом.
