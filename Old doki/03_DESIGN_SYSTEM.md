# Дизайн-система сайта «Море и Горы»

**Дата:** 2026-09-09
**Статус:** канон дизайн-системы первого релиза, версия 1.0
**Класс проекта:** коммерческий статический сайт на Next.js
**Источник визуальной правды:** `site-transfer-moreigori-2026-09-09/`
**Архитектура сайта:** `02_SITE_ARCHITECTURE.md`

## 1. Решение

Новый сайт сохраняет визуальный характер текущего `moreigori.ru`, но пересобирается чисто под static Next.js и новую SEO-архитектуру.

Визуальная формула:

```text
тёмно-синяя премиальная основа
+ белые скруглённые поверхности
+ коралловый акцент
+ крупные фото моря и гор
+ спокойная инвестиционная подача
```

Сайт должен ощущаться как инвестиционное бюро курортной недвижимости, а не как массовый агрегатор объявлений. В нём важны тишина, воздух, уверенность, дорогой природный визуал и ясная структура принятия решения.

## 3. Визуальные принципы

### 3.1. Премиальность без шума

Интерфейс должен быть спокойным: мало декоративных приёмов, крупные паузы, понятные блоки, аккуратные CTA. Не превращать сайт в «доску объявлений» и не перегружать первым экраном.

### 3.2. Фото как главный носитель эмоции

Главный визуальный материал — реальные изображения моря, гор, курортной архитектуры и объектов. Фото должны быть крупными, чистыми, без чрезмерного затемнения и без ощущения случайного стока.

### 3.3. Тёмная основа, светлые острова

Тёмно-синий фон задаёт статус и контраст. Белые скруглённые поверхности используются для hero, footer, форм, калькуляторов и важных смысловых блоков.

### 3.4. Коралловый акцент редко и точно

Коралловый цвет работает как сигнал действия. Его не нужно размазывать по всему интерфейсу: меню, главная кнопка, активный элемент, важная плашка.

### 3.5. SEO-текст должен быть видимым

Карусели и визуальные карточки можно использовать, но важный SEO-смысл должен быть в обычных HTML-секциях: заголовки, абзацы, списки, FAQ, таблицы, карточки объектов.

## 4. Цветовая система

| Token | Value | Назначение |
| --- | --- | --- |
| `--color-brand-navy` | `#08192c` | основной фон сайта, тёмные кнопки, headings, overlay |
| `--color-brand-coral` | `#ff6a55` | меню, CTA, активные состояния, важные акценты |
| `--color-surface-white` | `#ffffff` | hero, footer, светлые карточки, формы |
| `--color-text-dark` | `#1a1a1a` | тёмный текст на светлом фоне |
| `--color-text-light` | `#ffffff` | текст на тёмном фоне и фото |
| `--color-navy-74` | `rgba(8, 25, 44, 0.74)` | сильный overlay на фото |
| `--color-navy-50` | `rgba(8, 25, 44, 0.50)` | средний overlay |
| `--color-navy-35` | `rgba(8, 25, 44, 0.35)` | мягкий overlay |
| `--color-white-05` | `rgba(255, 255, 255, 0.05)` | едва заметные поверхности на тёмном фоне |

Правило: базовая страница не должна уходить в однотонную синюю массу. Нужны белые поверхности, фотографии и точечный коралл.

## 5. Типографика

| Role | Font | Использование |
| --- | --- | --- |
| Display | `EuropeExt, sans-serif` | H1, крупные брендовые заголовки, названия регионов |
| UI/body | `Montserrat, sans-serif` | навигация, кнопки, карточки, основной текст |
| Fallback | system sans | резервная загрузка |

Базовая шкала:

| Token | Desktop | Mobile | Use |
| --- | --- | --- | --- |
| `--text-body` | `16px / 24px` | `15-16px / 22-24px` | основной текст |
| `--text-caption` | `12-14px / 18px` | `12-13px / 16px` | подписи, meta |
| `--text-button` | `14-16px / 20-23px` | `12-14px / 18-20px` | pill buttons |
| `--text-card-title` | `28-32px / 36-40px` | `22-26px / 30-34px` | карточки, секции |
| `--text-section-title` | `40-56px / 52-70px` | `28-36px / 36-44px` | H2/H3 крупных блоков |
| `--text-hero` | `56-72px / 68-84px` | `30-42px / 38-50px` | H1 |

Запрет: не масштабировать шрифт напрямую от ширины viewport. Для responsive использовать фиксированные ступени через breakpoints.

Правило секций: каждый крупный блок должен иметь понятную роль и достаточно воздуха. Не переносить пустые Elementor-обёртки.

## 7. Компоненты

### 7.1. `SiteHeader`

Роль: шапка сайта.

Состав:

- логотип слева;
- меню или навигация;
- телефон;
- CTA в шапке при необходимости.

Визуально: компактная строка внутри hero или поверх тёмной/фото-секции. Коралловый pill можно оставить для меню.

### 7.2. `HomeHero`

Роль: первый экран главной.

Состав:

- белая скруглённая поверхность;
- крупное фото моря/гор;
- SVG map-line overlay;
- H1 про инвестиционную курортную недвижимость;
- короткое объяснение бюро;
- CTA: «Получить инвестиционный разбор», «Смотреть объекты» или «Сравнить регионы».

Требование: на первом экране должно быть видно бренд/категорию и намёк на следующий блок.

### 7.3. `Button`

Варианты:

- `primary`: тёмно-синий фон, белый текст;
- `accent`: коралловый фон, белый текст;
- `light`: белая кнопка на тёмном фоне;
- `ghost`: прозрачная кнопка/ссылка.

Форма: pill, uppercase допускается для коротких CTA. Не делать длинные кнопки с тяжёлым текстом.

### 7.4. `RegionCard`

Роль: переход к региону.

Состав:

- фото региона;
- overlay;
- название региона;
- короткий инвестиционный тезис;
- arrow/icon.

Важно: карточка должна быть обычной ссылкой. Если используется carousel, ссылки всё равно должны быть доступными и индексируемыми.

### 7.5. `ObjectCard`

Роль: показать отобранный объект.

Состав:

- фото;
- название;
- регион/локация;
- формат объекта;
- бюджет входа, если подтверждён;
- короткий инвестиционный тезис;
- CTA «Смотреть паспорт».

Не превращать карточку в WooCommerce product card. Это не товарная полка, а вход в инвестиционный паспорт.

### 7.6. `ObjectPassport`

Роль: страница объекта.

Состав:

- hero объекта;
- краткий вывод: кому подходит/не подходит;
- факты объекта;
- экономика;
- риски;
- локация;
- галерея;
- CTA на расчёт.

Можно использовать визуальную основу снятой страницы `Atlas Modern`, но смысловая структура должна соответствовать `02_SITE_ARCHITECTURE.md`.

### 7.7. `RegionHub`

Роль: SEO и коммерческая страница региона.

Состав:

- region hero с фото;
- инвестиционный тезис;
- кому подходит регион;
- рынок и сезонность;
- риски;
- объекты региона;
- связанная аналитика;
- FAQ;
- CTA.

Снятая страница Крыма — визуальный референс, не готовая SEO-структура.

### 7.8. `AnalyticsIndex`

Роль: список аналитических материалов.

Состав:

- H1;
- featured article;
- тематические группы;
- карточки статей;
- ссылки на регионы и объекты.

Текущий блог слишком простой, поэтому использовать его только как визуальный ориентир.

### 7.9. `ArticlePage`

Роль: экспертная статья.

Состав:

- H1;
- дата обновления;
- автор/ответственный;
- table of contents;
- содержательные H2;
- блоки выводов;
- связанные регионы/объекты;
- CTA на подбор.

Статья должна помогать SEO и продаже, а не быть изолированным блоговым постом.

### 7.10. `LeadForm`

Роль: квалифицировать обращение.

Минимальные поля:

- капитал;
- цель;
- горизонт;
- регион;
- допустимый риск;
- имя;
- телефон;
- согласие.

Визуально: тёмная или белая скруглённая панель, компактные поля, коралловая кнопка.

### 7.11. `SiteFooter`

Роль: финальная навигация и доверие.

Состав:

- меню;
- регионы;
- объекты/аналитика/методика;
- контакты;
- соцсети;
- юридические ссылки.

Старые footer links нужно заменить на новую архитектуру.

## 9. Imagery

Типы изображений:

- hero landscapes: море, горы, курортный горизонт;
- region images: узнаваемая природная/городская среда региона;
- object images: фасады, общественные пространства, интерьеры, окружение;
- analytical images: сдержанные, не случайный stock;
- decorative SVG: map-line overlays, arrows, small icons.

Правила:

- фото должны помогать понять регион/объект;
- не использовать чрезмерно тёмные или размытые изображения;
- alt обязателен для содержательных изображений;
- декоративные SVG можно скрывать от screen reader;
- большие изображения оптимизировать в WebP/AVIF и задавать стабильные размеры.

## 10. Motion и интерактив

Допустимо:

- лёгкое появление секций;
- hover на карточках;
- мягкий carousel/scroll для регионов;
- drawer/menu на мобильном.

Не нужно:

- переносить Elementor motion effects;
- скрывать важный контент до анимации;
- делать тяжелые lightbox/carousel без явной пользы;
- ломать доступность ради эффекта.

## 11. Responsive

### Desktop

- container около `1200px`;
- hero как крупная белая поверхность на тёмном фоне;
- карточки регионов/объектов в сетке или управляемой горизонтальной ленте;
- footer многоколоночный.

### Mobile

- hero должен оставаться читаемым, без горизонтального overflow;
- H1 уменьшается ступенчато;
- карточки становятся вертикальными или горизонтально прокручиваемыми;
- формы идут в одну колонку;
- footer становится stacked.

Критично: длинные русские слова и названия объектов не должны вылезать из кнопок/карточек.

## 12. Доступность и SEO

- Один H1 на странице.
- Семантические секции вместо вложенных декоративных div-слоёв.
- Кнопки для действий, ссылки для переходов.
- Все карточки объектов/регионов — обычные anchors.
- Фокус-состояния обязательны.
- Контраст текста на фото проверять вручную.
- Важный SEO-контент не должен быть только в carousel.
- Картинки с содержанием получают alt.

## 13. Что переносим точно

- Цветовую пару `#08192c` + `#ff6a55`.
- Белые скруглённые hero/footer поверхности.
- Большие фотографии моря/гор.
- Компактные pill-кнопки.
- Тёмный премиальный фон.
- Карточки регионов и объектов на фото.
- Идею карты/линий как мягкой графики.

## 14. Что не переносим

- WordPress, Elementor, WooCommerce runtime.
- Старую URL-структуру как SEO-канон.
- Пустые `h2` и пустые визуальные секции.
- Повторяющиеся carousel-слайды в DOM как SEO-контент.
- Индексируемые фильтры.
- Product-card модель WooCommerce.
- Неподтверждённые проценты доходности без источника и даты.

## 15. Implementation Notes

При сборке Next:

- сначала завести tokens и глобальные CSS variables;
- затем собрать `SiteHeader`, `SiteFooter`, `Button`, `SectionShell`;
- потом собрать `HomeHero`, `RegionCard`, `ObjectCard`;
- после этого шаблоны страниц;
- изображения брать из transfer package и нормализовать в будущую структуру `public/images/...`;
- CSS писать по проектной дизайн-системе, не по Elementor class names.
